# 9. agrelha Does Not Copy a World

Date: 2026-11-02

## Status

Accepted. Supersedes the **Duplicate** concept, removed from `CONTEXT.md` by
this decision.

## Context

`CONTEXT.md` defined **Duplicate** — "creating a new Instance from an existing
one, either by copying its World or by regenerating from the same Seed" — and
called it "the supported way to change what a World runs". Two rules leaned on
it: turning a Vanilla Instance Modded was "offered as Duplicate, never as an
edit", and Duplicate was "the supported path to a Modded copy".

No code implemented it. There was no Duplicate route, handler or manager method.
The word existed only in the glossary and in UI copy that pointed at a button
nobody had built — which is how it came to be written into the Settings page as
"to run a different version, duplicate this instance". A reader of the glossary
could not tell the concept from a feature.

What did exist was `RestoreNew`: restore a Backup into a *new* Instance, copying
the source's game config, Pack and Mod list, routed at
`POST /api/{game}/:num/backups/restore-new` and surfaced as "Restore as New
World". That is Duplicate's first half, arrived at from the backups side rather
than the instances side.

Three things made it the wrong half to keep:

1. **It could not do what Duplicate promised.** `RestoreNew` copied `Source` and
   `MCVersion` verbatim from the source Instance, so the copy was Vanilla if the
   original was, and on the same version. It answered neither "I want this world
   modded" nor "I want this world on a different version" — the two questions
   the glossary said Duplicate existed to answer.

2. **A copied World has no honest lineage.** Two Instances holding the same save
   diverge from the moment both start. Nothing in the model says which is the
   real one, and Incidents, Backups and player counts are per-Instance, so the
   history of a World silently splits in two.

3. **It undercut the Vanilla promise.** Vanilla is a promise that Steam
   achievements stay earnable. A route that produces a Modded copy of a Vanilla
   World is an escape hatch around a promise, and the copy is indistinguishable
   from the original to a player looking at a world list.

## Decision

**agrelha never copies a World.** A Backup belongs to the World it was taken
from and is only ever restored onto that World. Creating an Instance always
starts a new, empty World.

Consequently:

- The **Duplicate** concept is removed from the domain.
- **Backup** and **Restore** are defined as domain terms for the first time,
  scoped to a single World, so the gap that let Duplicate be mistaken for a
  feature cannot reopen.
- Changing a Pack, Loader or Minecraft version means a new Instance with a new
  World. The save does not come with it.
- A Vanilla Instance never gains mods **by any path**, not merely by editing.

## Consequences

`RestoreNew`, `ValheimRestoreNew`, both `/backups/restore-new` routes and the
"Restore as New World" modal are removed. Restoring over the source World is
unaffected and remains the only restore.

The honest cost: there is now no way to try a modpack against a copy of a played
world, or to keep a 1.21 save while standing up a 26.x server. Both were
previously possible for Minecraft only by accident of `RestoreNew` existing, and
neither worked the way the glossary claimed. A player who wants the old world
back restores its Backup onto it; a player who wants a different server gets a
new one.

This also removes the model's only mechanism for a World outliving its Instance,
which keeps "one Instance owns exactly one World" true without qualification.

## Alternatives considered

**Build Duplicate properly**, so it could change Source and version. Rejected:
it cannot change version in any useful sense, because the save is what blocks
the version change — a World generated by one version does not load on another,
so a "duplicate at a different version" is a new world wearing a borrowed name.

**Keep `RestoreNew` and rename the concept to match it.** Rejected: it keeps the
lineage problem and the Vanilla escape hatch, and the thing it is good at —
"give me a sandbox copy" — is not a thing the domain otherwise has a word for.

**Leave Duplicate in the glossary as aspirational**, marked unimplemented.
Rejected: it had already produced one wrong UI string in this repo, and a
glossary that describes things that do not exist is a glossary that cannot be
trusted for the things that do.
